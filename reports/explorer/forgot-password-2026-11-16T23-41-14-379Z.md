# Explorer: someone who forgot their password

- **Persona:** a customer with one booking who cannot remember the password.
- **Goal:** get back into the account.
- **Reached it:** yes, on the second code. It took 17 steps and one forced wait of about a minute.
- **Run folder:** `reports/explorer/runs/forgot-password-2026-11-16T23-41-14-379Z/`

## Steps taken
1. Opened Log in; clicked "Forgot password?" with the email empty: "Login failed. Email is required. (Reference: …)".
2. Typed an email with no account and clicked "Forgot password?": "Reset started. If that account exists, YardMatch has sent password recovery instructions." No code.
3. Closed it, typed my email, clicked "Forgot password?": same message plus "Local reset code: 425282". The reset form appeared below the login form, out of view.
4. Expired that code with the expire-reset tool.
5. Scrolled down, entered the code and a new password, clicked "Reset password".
6. At the top of the page: "Login failed. Password reset code has expired (Reference: …)". No offer to send a new code.
7. Clicked "Forgot password?" again within a minute: "Reset started …" again, but no new code was issued and nothing said to wait.
8. Waited about a minute; clicked "Forgot password?": a new code was issued.
9. The code field still held the old code; replaced it with the new one and entered a new password.
10. Clicked "Reset password": signed in and taken to the dashboard. No "password changed" message.
11. Checked the session from before the reset with the check-session tool: refused (401).
12. Opened the reset link form (`/login?resetCode=…&email=…`) while signed in: the login page with the reset form prefilled.
13. Entered a new password with the already-used code: "Login failed. Password reset code has expired (Reference: …)".
14. The same reuse through the API gave the same message.
15. The account's notification bell shows a new item ("Password updated", from the API).
16. Captured the login page and the reset link page at both sizes.
17. Done.

## Scenario checks
| Case | Result |
| --- | --- |
| Request | Works; the local code preview is shown. |
| Unknown email | Same wording as a real account; no code. No account enumeration. |
| Expired code | Rejected ("Password reset code has expired"). |
| Reused code | Rejected, but with the same "has expired" wording. |
| Old sessions | The session from before the reset is refused (401). |
| Old password | Not tried in the browser; the bot run confirms it is refused. |

## Findings

### 1. Asking again within a minute silently sends nothing (bug, high)
- **Repeat:** request a reset, then request again within 60 seconds (for example after an expired-code error).
- **Expected:** a new code, or "Wait a minute before asking for another code."
- **Happened:** the same "Reset started" message appears and no code is issued. A person who just hit "expired" will wait for an email that never comes.

### 2. Reset errors are headed "Login failed" and sit at the top of the page (friction, medium)
- **Repeat:** submit an expired or used code, or click "Forgot password?" with no email.
- **Happened:** the error shows above the login form with the heading "Login failed" and a "(Reference: uuid)" suffix, while the reset form is further down the page. It doesn't say what to do next (copy rule: errors say what to do next).
- **Screenshot:** `01-login-1440x900.png`

### 3. No "Send a new code" after an expired or used code (gap, medium)
- **Happened:** the only way forward is to scroll up and click "Forgot password?" again, which also needs the email field to still be filled.

### 4. A used code is described as "expired" (friction, low)
- **Happened:** reusing a code that already worked says "Password reset code has expired". It should say the code was already used.

### 5. The reset form opens out of view (friction, medium)
- **Repeat:** click "Forgot password?" on a laptop-height window.
- **Happened:** the code and new-password fields appear below the login and social buttons; on a phone they are well below the fold, with no scroll or focus change.
- **Screenshot:** `02-reset-link-390x844.png`

### 6. No confirmation that the password changed (gap, low)
- **Happened:** after a successful reset you land on the dashboard with no message. The "Password updated" notice exists only in the bell.

### 7. New password has no confirm field and no rules shown (friction, low)
- **Happened:** one password field and no strength rules until an error. Sign-up shows the rules ("At least 8 characters with uppercase, lowercase, and a number").

### 8. The reset link opens the login page while you're signed in (friction, low)
- **Happened:** the header shows the signed-in account while the page says "Log in", with the reset form below.

## Places I had to guess
- Whether a second "Reset started" meant a new code was on its way.
- Whether the old code would still work after asking for a new one.
