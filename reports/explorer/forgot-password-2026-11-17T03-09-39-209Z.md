- Persona: someone who booked a mowing a while ago and can't remember their password (explore-forgot-password-owner-900@example.invalid).
- Goal: get back into the account.
- Reached: yes. The reset signed me straight into the customer dashboard, and later I logged in normally with the new password.
- Effort: 9 steps on the shortest path (home, Log in, type email, Forgot password?, scroll, enter code and password, submit, dashboard). The full run with all the "Also check" items took about 40 steps.

## 3. Findings

### A short new password crashes the reset with a generic "something went wrong on our end" error
**bug**, severity **high**

Steps to repeat:
1. Go to /login and enter the account email.
2. Click "Forgot password?" and copy the code.
3. Enter the code and a short password such as `abc`.
4. Click "Reset password".

Expected: a message saying what the password needs (for example a minimum length), shown next to the New password field. The field should also state the rules before I type.

What happened: the top of the card says "Login failed" and then "Something went wrong on our end. Please try again. If it keeps happening, contact support. (Reference: fb2305f5-...)". In api.log, `POST /api/auth/password-reset/confirm` returned **500** with the error thrown from `validatePasswordStrength`. Nothing on the page states the password rules, so trying again with the same kind of password fails the same way. A locked-out person is told to contact support for what is really a validation error. That's why I rated it high.

Screenshots: `runs/forgot-password-2026-11-17T03-09-39-209Z/09-weak-password-generic-error-offscreen-browser.jpg`

### Reset errors appear at the top of the login card under "Login failed", off screen from the reset form
**friction**, severity **medium**

Steps to repeat:
1. Request a code.
2. Expire it (`expire-reset`) or type a wrong or used code.
3. Scroll down to the reset form and click "Reset password".

Expected: the error appears next to the Reset code field, with a heading about the reset.

What happened: the view near the button doesn't change at all (06). The error is placed above the Email field, at the top of the card, under the heading "Login failed" (07, 13). I hadn't tried to log in. This "Login failed" heading also appears when clicking "Forgot password?" with an empty email (03). The submitted code is cleared, so it looks like the page just reset itself.

Screenshots: `06-expired-code-submitted-no-visible-error-browser.jpg`, `07-expired-error-at-top-login-failed-browser.jpg`, `13-reused-code-invalid-browser.jpg`, `03-forgot-empty-email-browser.jpg`

### "Ask for a new code" leads straight to a "wait a minute" block
**friction**, severity **medium**

Steps to repeat:
1. Request a code.
2. Expire it.
3. Submit it, which shows "This code has expired. Ask for a new code."
4. Click "Forgot password?" right away.

Expected: either a new code is sent, or the expired-code message says how long to wait. The reset form should also have its own "Send a new code" action.

What happened: "Reset started / A code was just requested for this email. Wait a minute, then ask again if it hasn't arrived." The heading says "Reset started" even though nothing was sent. There's no resend control inside the reset form, so you have to scroll back up to the small "Forgot password?" link.

Screenshots: `07-expired-error-at-top-login-failed-browser.jpg` (the throttle text is visible in 14 for the unknown-email case)

### "Invalid password reset code" doesn't say what to do next
**friction**, severity **low**

Steps to repeat: complete a reset with a code, then request the form again and submit the same code.

Expected: something like "This code was already used. Ask for a new code." The expired-code message already does this well.

What happened: "Invalid password reset code", with no next step, under "Login failed". Reuse is correctly blocked.

Screenshots: `13-reused-code-invalid-browser.jpg`

### The only way to open the reset form also requests a new code
**gap**, severity **low**

Steps to repeat: request a code, close the tab or sign out, then come back to /login with the code from your email.

Expected: a way to enter a code you already have, such as a reset page linked from the email.

What happened: the reset form only appears after clicking "Forgot password?", and that click always asks for another code. That code replaces the one in your inbox (or you get throttled), which makes mixing up emails likely.

### The reset form appears below the social sign-in buttons, mostly below the fold
**friction**, severity **low**

Steps to repeat: on /login, enter your email and click "Forgot password?" at 1440x900 or 390x844.

Expected: the login form switches to a reset view, or the page scrolls to the reset section.

What happened: the "Reset your password" section is added under "Continue with Google", "Continue with Apple" and "Create an account". The Reset code and New password fields are below the fold on both desktop and mobile. The Email and Password login fields stay visible above it, so there are two password fields on the page, and it's easy to type the new password into the login "Password" field.

## 4. Guesses, confirmations, and other notes

- **Guessed:** the password rules. Nothing on the reset form states them, and the weak-password error doesn't either.
- **Guessed:** where errors would appear after "Reset password". I only found them by scrolling to the top of the card.
- **Guessed:** that "Forgot password?" is the way to resend a code. There is no resend control inside the reset form.
- **Missing confirmation:** nothing on screen confirms the password change; it's only in the notification bell. No email could be checked locally.
- **Done right:**
  - Expired codes are rejected with a clear next step.
  - Used codes are rejected.
  - The session from before the reset gets 401.
  - A "Password updated" notification is created.
  - Wording and throttling are the same for real and unknown emails.
- **Local-only behaviour to confirm before launch:** for a real account the page shows "Local reset code: NNNNNN" on screen, and for an unknown email it doesn't. That's fine as a dev aid, but in production it would both bypass email ownership and reveal which emails have accounts. Confirm it can never render outside local mode.
- **Environment note:** the "Continue with Google/Apple" links on :3012 use `redirectUri=http://localhost:3000/auth/complete`. That probably comes from this run's port setup, not the product, but OAuth would return to the wrong origin on this instance.
- **Capture tool limit:** the capture tool doesn't use the browser session. `11-dashboard-after-reset-*.png` shows the signed-out "Log in to your account" view, not the signed-in dashboard. Interaction states were saved from the browser pane as `*-browser.jpg` at the pane's 1024x768 viewport (and 390x844 for 14).
- **Not a product issue:** an early Sign out looked like it failed because I navigated away before it finished. Signing out again normally worked.
